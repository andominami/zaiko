# 院内在庫ボード

文房具・歯科材料などの在庫と発注を管理するサイトです。
GitHub Pages で公開し、データは Firebase（Firestore）に保存します。

- ログインはありません。**専用リンク（最後に `#k=...` が付いたもの）を知っている人だけ**が使えます。
- 専用リンクの `#k=` 以降はどのファイルにも書かれていません。そのため、このリポジトリが公開されていても在庫データは見られません。
- 一度専用リンクで開いた端末では、次から `https://<アカウント名>.github.io/zaiko/` だけで開けます。
- 発注点は「1日の使用量 ×（納期 ＋ 予備の日数）」で自動計算します。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 画面とデザイン |
| `app.js` | 動き（在庫の計算、保存など） |
| `firebase-config.js` | Firebase の接続設定（手順2で書き換えます） |
| `firestore.rules` | データを守るルール（手順2で Firebase に貼り付けます） |

## はじめの準備

### 1. Firebase のプロジェクトを作る

1. <https://console.firebase.google.com/> を開き、Google アカウントでログインします。
2. 「プロジェクトを作成」（または「Firebase プロジェクトを始める」）を押します。
3. 名前は `zaiko-board` など、分かりやすいものにします。
4. Google アナリティクスは **オフ** で大丈夫です。
5. 作成が終わるまで待ちます。

### 2. データベースとルールを設定する

1. 左のメニューの「構築」→「Firestore Database」→「データベースを作成」を押します。
2. 場所は **`asia-northeast1 (Tokyo)`** を選びます（あとから変更できません）。
3. 「本番環境モードで開始」を選んで作成します。
4. 上のタブの「ルール」を開きます。中身を全部消し、このリポジトリの `firestore.rules` の中身を貼り付けて「公開」を押します。

### 3. Web アプリを登録して設定をコピーする

1. 左上の歯車 →「プロジェクトの設定」を開きます。
2. 下の方の「マイアプリ」で `</>`（ウェブ）のアイコンを押します。
3. アプリの名前を入れます（例：`zaiko`）。「Firebase Hosting も設定する」には **チェックを入れません**。
4. 「アプリを登録」を押すと、`const firebaseConfig = { ... }` という設定が表示されます。
5. `firebase-config.js` の `export default { ... }` の中身を、表示された `apiKey` 〜 `appId` の値に置き換えます。

   ```js
   export default {
     apiKey: "AIza....",
     authDomain: "zaiko-board-xxxx.firebaseapp.com",
     projectId: "zaiko-board-xxxx",
     storageBucket: "zaiko-board-xxxx.appspot.com",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef",
   };
   ```

   この値は公開されても問題ない情報です（データはルールと専用リンクで守られています）。

### 4. GitHub に置いて公開する

1. GitHub で「New repository」を押し、名前を `zaiko` にします。**Public** を選んで作成します。
2. 「uploading an existing file」（または「Add file」→「Upload files」）を押します。`index.html`・`app.js`・`firebase-config.js`・`firestore.rules`・`README.md` の5つをドラッグして「Commit changes」を押します。
   - **移行用データの .json ファイルはアップロードしないでください。**
3. リポジトリの「Settings」→ 左の「Pages」を開きます。
4. 「Branch」を `main`、フォルダを `/ (root)` にして「Save」を押します。
5. 1〜2分待つと、`https://<アカウント名>.github.io/zaiko/` でサイトが開けるようになります。

### 5. 在庫ボードを作ってデータを移す

1. `https://<アカウント名>.github.io/zaiko/#new` を開き、「新しい在庫ボードを作る」を押します（最後に `#new` を付けたときだけボタンが出ます）。
2. アドレスが `...#k=（ランダムな文字）` に変わります。**このアドレスが専用リンクです。** すぐにブックマークしてください。
3. 「設定」タブ →「データの読み込み」で移行用の .json ファイルを選び、「読み込む」を押します。
4. 「設定」タブでこの端末の名前を入れて保存します。
5. 「設定」タブの「この在庫ボードのリンク」をコピーして、スタッフにだけ共有します。

## ふだんの使い方

- **発注タブ**：今注文するもの・入荷待ちの一覧です。「注文した」「届いた」を押して記録します。
- **在庫一覧タブ**：分類ごとの在庫です。「−」「＋」で数を変えます。品目名をタップすると、細かい設定ができます。
- **履歴タブ**：誰がいつ何を動かしたかの記録です。
- **設定タブ**：端末の名前、専用リンクのコピー、バックアップ、データの読み込みができます。

月に1回くらい、「設定」→「バックアップを保存」でファイルを保存しておくと安心です。

## 修正するとき

GitHub でファイルを開き、鉛筆マーク（Edit）で書き換えて「Commit changes」を押します。1〜2分でサイトに反映されます。
変更の履歴は GitHub に残るので、おかしくなったときは前の状態に戻せます。

## 専用リンクが外に漏れたとき

1. 「設定」→「バックアップを保存」でファイルを保存します。
2. 新しいタブで `https://<アカウント名>.github.io/zaiko/#new` を開きます。そこで「新しい在庫ボードを作る」を押し、バックアップを読み込みます。
3. 新しいリンクをスタッフに共有し直します。
4. Firebase の画面の「Firestore Database」→「データ」で、古いリンクの文字と同じ名前のデータを削除します。
